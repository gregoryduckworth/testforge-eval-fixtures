# Test strategy: GAPS-20261122-1C2C Keep API tests in step with the spec

Revision 1 · generated by TestForge

## Summary

The Orders API spec replaced getOrder's `totalCents` with a required `total` Money object ({amount, currency}), allowed status `cancelled`, and added POST /orders/{id}/cancel (200 Order, 404, 409). The tests in test/orders.test.js must assert the new getOrder shape (changing only the totalCents assertion of the existing test) and cover cancelOrder's success and documented errors, against the real in-process app.

## Scope

**In scope**
- GET /orders/{id} 200 response shape (total replaces totalCents; status cancelled)
- POST /orders/{id}/cancel 200, 404, 409

**Out of scope**
- Operations the spec didn't change (products, POST /orders, GET /orders/{id} 404 already tested and unchanged)

## Test case detail

### TC1: returns an order with its total

*integration · vitest · regression · critical priority* — covers AC1

**Preconditions**
- App listening on an OS-chosen port

**Steps**
1. Place an order for product 1, quantity 2
2. GET /orders/{id}

**Expected:** 200, body equals {id, productId: 1, quantity: 2, status: 'placed', total: {amount: 4998, currency: 'USD'}}

**Test data:** product 1 (Kettle, 2499c)

**Rationale:** getOrder (GET /orders/{id}): spec replaced totalCents with required total object; existing test at line 48 asserted the old contract. Only that property changes.
