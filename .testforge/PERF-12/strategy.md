# Test strategy: PERF-12 The order page has got slow

Revision 1 · generated by TestForge

## Summary

GET /orders/:id got slower when commit 62d8c6f ("Show each line's product name on an order") was added. In src/app.js:33 that commit calls findProduct() once for each line, one after another. Every store query is a simulated round trip of 6–9 ms (src/store.js), and an order has 8 lines, so the page now makes 10 sequential queries where it used to make 2: findOrder + orderLines ≈ 15–18 ms before, ≈ 75–90 ms now. That matches the reported change from about 22 to 88 ms p95. The plan is to guard the detail scenario in perf/orders.js with a scenario-scoped k6 threshold that fails while the page stays this slow, and to record the N+1 query as a defect for the API team. The application is not changed.

## Scope

**In scope**
- perf/orders.js: thresholds scoped to the detail scenario (p95, p99, error rate)
- Request name tag on the detail request so /orders/:id is aggregated as one URL
- Defect record of the N+1 product lookup

**Out of scope**
- Changing src/ (the fix belongs to the API team, per the ticket)
- perf/search.js and the list scenario's limits (the ticket says both are fine)
