### TC1: detail scenario keeps p95 and p99 latency within 20% of the last good runs

*performance · k6 · performance · high priority* — covers AC1, AC2

**Preconditions**
- orders API running at BASE_URL

**Steps**
1. Run perf/orders.js under its constant-arrival-rate scenarios
2. k6 evaluates 'http_req_duration{scenario:detail}': ['p(95)<26.4', 'p(99)<27.6']

**Expected:** Thresholds pass when the detail latency is at baseline. They fail now (p95 30 ms, p99 33 ms) until the extra round trip is removed.

**Rationale:** Commit 72802a9 added productNames(), a separate awaited store query on every GET /orders/:id after findOrder and orderLines. That takes the request from 2 sequential round trips (6–9 ms each) to 3, about +8 ms, which matches the measured slowdown. The commit message says the names come 'in one query with the lines', but the code makes a separate query.
