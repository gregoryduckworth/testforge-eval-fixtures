# Test strategy: API-31 Search and page through products

Revision 1 · generated by TestForge

## Summary

GET /products filters by case-insensitive name substring `q`, pages results with `limit`/`offset` (limit capped at MAX_LIMIT), reports `total` matches, and refuses non-whole-number limit/offset or limit < 1 with 400. Tests start the real app in-process (createApp on an OS-chosen port, as the existing suite does) and assert on the fixed in-memory catalogue.

## Scope

**In scope**
- GET /products query filtering, paging, total, limit cap and parameter validation

**Out of scope**
- GET /products/:id and POST /orders (not part of this ticket)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | `q` returns only products whose name contains it, case-insensitively; without `q` every product is listed. | TC1, TC2, TC4 |
| AC2 | Results are returned one page at a time per `limit` and `offset`, the response's `total` is the number of all matches, and a limit above the maximum is capped to it. | TC2, TC3, TC4, TC5, TC6, TC9 |
| AC3 | A `limit` or `offset` that isn't a whole number, or a `limit` below 1, gets 400. | TC7, TC8, TC9 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Case-insensitive matching broken (e.g. only lowercasing one side) | high | TC1 searches with mixed case and checks every match and the total |
| total reports page size instead of match count | high | TC3/TC4 assert total stays the full match count while items is a page |
| Loose validation lets negative/decimal values through, causing odd slices | medium | TC7-TC9 cover decimal, negative, non-numeric, zero and the valid boundary |

## Environment

No external services; the suite starts the app in-process on an OS-chosen port, run by the existing `npm test`.

## Assumptions

- The real app runs in-process via createApp() on port 0; nothing is faked. The catalogue (src/catalogue.js) is the fixed 120-product list, so totals like 15 Kettles are known; GET /products never mutates it.
- The cap is the exported MAX_LIMIT constant (50 in code); tests import it rather than hard-coding a number.
- Results are ordered by id (catalogue order), as the README states.
