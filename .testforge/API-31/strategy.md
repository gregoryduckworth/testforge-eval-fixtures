# Test strategy: API-31 Search and page through products

Revision 1 · generated by TestForge

## Summary

GET /products filters the in-memory catalogue (120 products, 8 names × 15) by case-insensitive name substring `q`, pages with `limit` (default 20, capped at MAX_LIMIT=50) and `offset`, returns { total, items }, and refuses non-whole limit/offset or limit < 1 with 400. Tests start the real app in-process and call it over HTTP to prove filtering, paging, the cap and the refusals.

## Scope

**In scope**
- GET /products query handling: q, limit, offset, total, cap, 400 refusals

**Out of scope**
- GET /products/:id and POST /orders (not in the ticket)
- Search box UI (no UI in this repo)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | q matches products whose name contains it, case-insensitively; without q every product is listed. | TC1, TC2, TC3, TC4 |
| AC2 | Results are paged with limit and offset, the response gives the total number of matches, and limits above MAX_LIMIT (50) are capped. | TC5, TC6, TC7 |
| AC3 | A limit or offset that isn't a whole number, or a limit below 1, is refused with 400. | TC8, TC9, TC10, TC11 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Search becomes case-sensitive or prefix-only, so the shop's search box misses products | high | TC1 uses mixed-case q, TC2 a substring from the middle of a name |
| total reports the page size instead of all matches, breaking pagination | high | TC5 asserts total 15 while the page has 5 items |
| Uncapped limit lets clients pull the whole catalogue | medium | TC7 asks for more than MAX_LIMIT and expects exactly MAX_LIMIT items |
| Malformed paging values accepted silently (e.g. 2.5 parsed as 2) | medium | TC9–TC11 one row per invalid value |

## Environment

## Assumptions

- The limit cap is 50 (MAX_LIMIT in src/app.js), not the README's 100: a person confirmed this in earlier runs on API-31 (approved repo note); tests import MAX_LIMIT.
- The real app runs in-process on port 0 for every test; nothing is faked. The catalogue is fixed in src/catalogue.js and GET /products does not change it.
- Server start/stop moves into a shared helper test/helpers/server.js used by both test/products.test.js and the new spec.
