# Test strategy: API-31 Search and page through products

Revision 1 · generated by TestForge

## Summary

GET /products (src/app.js listProducts) filters the in-memory catalogue by case-insensitive name substring `q`, pages with `limit` (default 20, capped at MAX_LIMIT=50) and `offset`, returns { total, items }, and refuses non-whole-number limit/offset or limit < 1 with 400. Integration tests start the real app on an OS-chosen port (as test/products.test.js does) and prove search, paging, total, the cap and the refusals.

## Scope

**In scope**
- GET /products query q, limit, offset, total and items
- 400 refusals for invalid limit/offset

**Out of scope**
- GET /products/:id and POST /orders (not in this ticket)
- The shop UI's search box (no UI in this repo)

## Assumptions

- The real app runs in-process on port 0; nothing is faked. The catalogue is the fixed 120-product list in src/catalogue.js (8 names x 15), so expected results are known: e.g. 'kettle' matches Kettle 1..15, 'tea' matches 30 (Teapot + Tea strainer).
- Results are ordered by id (catalogue order), as the README states.
