# Test strategy: SMOKE-20261120-9850 Smoke check a deployment

Revision 1 · generated by TestForge

## Summary

The shop (catalogue, product pages, cookie cart, checkout) has no smoke suite. Add tests/shop.smoke.spec.js: five fast Playwright tests, each tagged @smoke, that reach the app only through the configured baseURL (BASE_URL when set) and only read. Together they show the build is up, its catalogue, product pages, cart and checkout page are reachable and show what a shopper expects. Placing an order is not done, because it is the only request that writes data on the server.

## Scope

**In scope**
- GET /health
- Catalogue home page
- Product page reached from the catalogue
- Adding to the cart (a browser cookie only; no server request) and the cart page
- Checkout page rendering its order form (not submitted)

**Out of scope**
- Placing an order (POST /orders): it is the only request that writes server data, so it is left to the existing checkout.spec.js
- Error paths (404, empty cart, form validation): a smoke suite checks critical paths only
- Running the suite in this run: the target is a non-disposable deployed build; the PR's CI runs it

## Environment

BASE_URL selects a deployed build; without it playwright.config.js starts node src/server.js on localhost:4175. CI (.github/workflows/ci.yml) runs `npx playwright test`, which includes the new file; smoke runs filter with `--grep @smoke`.

## Assumptions

- Adding to the cart counts as read-only: public/app.js writes only the browser's cart cookie and sends no request, and README says POST /orders is the only request that changes anything on the server. Each Playwright test has its own browser context, so the cookie never outlives the test.
- The catalogue is code (src/catalogue.js PRODUCTS), not seeded data, so every environment of the same build shows it; the tests import PRODUCTS/formatPrice rather than copying names and prices.
- No first-party service is faked: without BASE_URL the config starts the real server (node src/server.js); with it the tests hit the deployed build.
