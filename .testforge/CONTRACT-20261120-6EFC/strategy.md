# Test strategy: CONTRACT-20261120-6EFC Keep API tests in step with the spec

Revision 1 · generated by TestForge

## Summary

The Orders API spec changed: GET /orders/{id} now returns `total` (Money: amount in cents + currency USD|EUR) instead of `totalCents`, and its status may be `cancelled`; a new POST /orders/{id}/cancel operation returns the cancelled Order (200), 404 for an unknown order and 409 when already cancelled. The tests must bring the existing getOrder assertion up to the new shape and cover cancelOrder's success and documented errors, in test/orders.test.js against the real app started in-process.

## Scope

**In scope**
- GET /orders/{id} 200 body shape (total object replaces totalCents)
- GET /orders/{id} showing status `cancelled` after a cancel
- POST /orders/{id}/cancel: 200, 404, 409 with the spec's body shapes

**Out of scope**
- Unchanged operations (products, POST /orders)
- Stock restored on cancel (not in the spec)
