# Test strategy: ROOM-7 Book meeting rooms

Revision 1 · generated by TestForge

## Summary

createBookings() (src/bookings.ts) validates bookings (room, owner, half-hour UTC start, 30–240 min in 30-min steps), refuses same-room overlaps, lists a room's bookings by start time and lets only the owner cancel. Unit tests with Vitest against the real code and memoryStore() prove each rule and its refusal, asserting BookingError and the reason it gives.

## Scope

**In scope**
- book(): room, owner, start and length validation
- Overlap rules per room, including touching bookings
- list() ordering and per-room scoping
- cancel(): owner-only, freeing the slot, unknown id

**Out of scope**
- The app's database-backed BookingStore (not in the repo); tests use memoryStore() as the README says

## Assumptions

- memoryStore() is the store the tests use, as README.md says; no fakes are written.
- The reason a booking is refused is shown by the BookingError message from src/bookings.ts (the only thing distinguishing refusals), so tests assert the exact message.
- Owner names are matched after trimming whitespace, as the code does; matching is case-sensitive.
- The at('HH:MM') builder moves to test/support/time.ts and is shared by both spec files.
