# Test strategy: ROOM-7 Book meeting rooms

Revision 1 · generated by TestForge

## Summary

createBookings() books, lists and cancels meeting rooms against a BookingStore (memoryStore in tests). The tests must prove the booking rules (room, owner, UTC half-hour start, 30–240 min length in 30-min steps) with a BookingError naming the reason, the same-room overlap rule including back-to-back and cross-room bookings, listing by start time, and owner-only cancellation that frees the slot.

## Scope

**In scope**
- createBookings().book / list / cancel with memoryStore()
- BookingError type and its message for each refusal

**Out of scope**
- The app's database-backed BookingStore (not in this repository)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | A booking must name room Atlas, Borealis or Cosmos and a non-blank owner, start on the hour or half hour in UTC, and last 30–240 minutes in 30-minute steps; otherwise book() rejects with a BookingError whose message says why. | TC1, TC2, TC3, TC4, TC5, TC6 |
| AC2 | A booking overlapping another booking of the same room is rejected with a BookingError; bookings of different rooms never clash and a booking may start exactly when another ends. | TC7, TC8, TC9 |
| AC3 | list(room) returns that room's bookings ordered by start time. | TC10 |
| AC4 | Only the booking's owner can cancel it (others get a BookingError and the booking stays); cancelling removes it and frees its time for a new booking. | TC11, TC12, TC13 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Off-by-one in overlap check (<= vs <) would refuse back-to-back bookings or allow touching overlaps | high | TC9 books exactly adjacent slots on both sides; TC7 covers every overlap shape including 30-minute partial overlaps |
| Length/start validation boundaries (30, 240, non-multiples, non-UTC offsets) drift | medium | TC4–TC6 table the boundary values on both sides |
| A non-owner can cancel, or cancelling leaves the slot blocked | high | TC11 rebooks the freed slot; TC12 shows the booking survives a stranger's cancel |

## Test case detail

### TC1: books each of the rooms Atlas, Borealis and Cosmos on the half hour

*unit · vitest · positive · high priority* — covers AC1

**Preconditions**
- fresh createBookings()

**Steps**
1. it.each over ROOMS: book room, owner 'ada', start 09:30Z, 30 minutes

**Expected:** Returns booking {id 1, room, owner 'ada', start 09:30Z, end 10:00Z}

**Test data:** ROOMS imported from src/bookings

**Rationale:** Proves every named room and a half-hour start are accepted

### TC2: refuses a room that is not Atlas, Borealis or Cosmos

### TC7: refuses a booking that overlaps another booking of the same room

*unit · vitest · negative · critical priority* — covers AC2

**Preconditions**
- Atlas booked 10:00–11:00Z by ada

**Steps**
1. it.each overlap shape: same slot, starts inside (10:30 60m), ends inside (09:30 60m), contains (09:00 180m), contained (10:00 30m): bob books Atlas
2. list Atlas

**Expected:** Rejects with BookingError 'Atlas is already booked from 2026-03-02T10:00:00.000Z.'; list holds only ada's booking

**Rationale:** Core double-booking rule, every overlap shape

### TC8: books different rooms for the same time

## Assumptions

- Unit tests against the real createBookings() with the real memoryStore(); nothing is faked.
- "Says why" is checked by asserting the exact message src/bookings.ts gives each refusal (the module under test is the only source of these messages), plus that the error is a BookingError.
- Room names match exactly (case-sensitive), as the code does: 'atlas' is refused.
- A start is on the hour/half hour only if it has zero seconds and milliseconds in UTC; a local offset like +05:45 that lands on :15 UTC is refused.
