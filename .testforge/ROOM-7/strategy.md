# Test strategy: ROOM-7 Book meeting rooms

Revision 1 · generated by TestForge

## Summary

ROOM-7 covers createBookings() in src/bookings.ts: validating a booking (room, owner, start on the UTC hour/half hour, 30–240 minutes in 30-minute steps), refusing overlaps within a room, listing by start time and owner-only cancellation. Unit tests with Vitest against the real code and memoryStore() prove each rule and each refusal (BookingError with its reason).

## Scope

**In scope**
- book(): validation of room, owner, start alignment (UTC) and length, with BookingError and its reason
- book(): clash detection within a room, no clash across rooms, back-to-back bookings
- list(): ordering by start time and per-room filtering
- cancel(): owner-only, unknown id, freeing the time

**Out of scope**
- The app's database-backed BookingStore (not in this repository); tests use memoryStore() as the README says

### TC2: refuses a room that is not one of the office's rooms

## Assumptions

- Room names are matched exactly (case-sensitive), as the code does: 'atlas' is not a room.
- The owner is trimmed; a blank or whitespace-only owner is refused. Cancelling compares the trimmed name exactly.
- 'Says why' is checked by asserting the BookingError's exact message from src/bookings.ts, since the message is the only thing telling refusals apart.
- Tests run fully in memory with memoryStore(); no services are needed.
