# Test strategy: ROOM-7 Book meeting rooms

Revision 1 · generated by TestForge

## Summary

createBookings() (src/bookings.ts) validates a booking's room, owner, UTC half-hour start and 30-minute-step length up to 4 hours, refuses clashes within a room, lists a room's bookings by start and lets only the owner cancel. Unit tests with Vitest against the real memoryStore() prove each rule, its boundaries and each refusal (BookingError with the reason).

## Scope

**In scope**
- book(): room, owner, start and length validation, with the BookingError message
- book(): overlap rules within a room, across rooms and back-to-back
- list(): order by start time, only the room's bookings
- cancel(): by owner frees the time; by someone else or for an unknown id is refused

**Out of scope**
- The app's database-backed BookingStore (not in this repository); tests use memoryStore() as the README says

## Environment

No services; Vitest unit tests via `npm test` against memoryStore().

## Assumptions

- Room names match exactly (case-sensitive), as the code does: 'atlas' is refused.
- An owner name is trimmed; a blank or whitespace-only owner is refused, as the code does.
- A start given with a non-UTC offset is judged by its UTC instant (09:00+05:45 is 03:15Z, off the half hour).
- The refusal messages in src/bookings.ts are the 'says why' of AC1; tests assert them exactly since they are the output under test.
- Tests run against memoryStore() (the real in-memory store), with a fresh createBookings() per test; nothing is faked.
- The at('HH:MM') date helper moves to test/support/time.ts and the existing test/bookings.test.ts imports it from there.
