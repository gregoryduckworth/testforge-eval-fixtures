## Test case detail

### TC1: returns an order with its total

*integration · vitest · regression · critical priority* — covers AC1

**Preconditions**
- App running in-process

**Steps**
1. Place an order for 2 Kettles (productId 1)
2. GET /orders/{id}

**Expected:** 200 and body exactly { id, productId: 1, quantity: 2, status: 'placed', total: { amount: 4998, currency: 'USD' } }

**Test data:** productId 1, quantity 2

**Rationale:** The existing test asserts the old totalCents field; update it to the spec's Money shape.

### TC2: cancels a placed order and returns it

*integration · vitest · positive · critical priority* — covers AC2

**Preconditions**
- A freshly placed order

**Steps**
1. Place an order for 1 Mug (productId 3)
2. POST /orders/{id}/cancel

**Expected:** 200 and body exactly { id, productId: 3, quantity: 1, status: 'cancelled', total: { amount: 699, currency: 'USD' } }

**Test data:** productId 3, quantity 1

**Rationale:** Success response of the new operation, shaped as the spec's Order.

### TC3: shows the order as cancelled once cancelled

*integration · vitest · positive · high priority* — covers AC2

**Preconditions**
- A freshly placed order

**Steps**
1. Place an order
2. Cancel it and check 200
3. GET /orders/{id}

**Expected:** GET returns 200 with status 'cancelled'

**Test data:** productId 3, quantity 1

**Rationale:** Proves the cancel persists rather than only being reflected in its response.

### TC4: is 404 for cancelling an unknown order

**Test data:** id 999

### TC5: is 409 for cancelling an order already cancelled

*integration · vitest · negative · high priority* — covers AC2

**Steps**
1. Place an order
2. Cancel it and check 200

**Expected:** Second cancel is 409 with body { error: <string> }

**Test data:** productId 3, quantity 1

**Rationale:** Documented 409 response.

## Assumptions

- The real app runs in-process (createApp on port 0) as the existing spec does; nothing is faked.
- Each test places its own order, so ids come from the response, not from order of execution.
- Currency is USD because store.js sets it for every order; amount is priceCents × quantity in cents (Kettle 2499 × 2 = 4998).
- Modifying the existing GET-with-total test in place (its title kept) is the 'API tests assert the total as the spec describes'; all other existing tests stay byte-identical.
- Cancel tests go in test/orders.test.js, reusing its inline server setup and placeOrder helper, rather than a new file.
