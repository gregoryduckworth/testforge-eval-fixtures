# Test strategy: SMOKE-20261120-3155 Smoke check a deployment

Revision 1 · generated by TestForge

## Summary

Add a small, read-only Playwright smoke suite (tests/shop.smoke.spec.js, every test titled with @smoke) for the Kettle & Co. tea shop that checks a deployed build's critical paths through the configured baseURL (BASE_URL, or the locally started shop): the health endpoint answers, the catalogue lists the products, a product page opens from it, adding to the cart (a browser cookie only, no server request) shows in the cart, and the checkout form is reachable. No test submits an order or sends POST/PUT/PATCH/DELETE.

## Scope

**In scope**
- GET /health status and body
- Catalogue page (/) heading and product links
- Product page reached from the catalogue: heading, price, Add to cart button
- Add to cart (client-side cookie) reflected on the cart page: line, quantity, total, header count
- Checkout page with a cart: order form fields and Place order button visible (not submitted)
- A test:smoke npm script that runs only @smoke tests

**Out of scope**
- Placing an order (POST /orders) and the order confirmation page: it writes data on the server, so it is left to the full e2e suite (tests/checkout.spec.js)
- Error paths (404 page, empty-cart checkout refusal, 405) — smoke covers critical paths only
- Running the tests in this run: the target is a deployed, non-disposable build; the PR's CI runs them

## Environment

Playwright baseURL is BASE_URL when set (deployed build); otherwise playwright.config.js starts `node src/server.js` on localhost:4175. CI (.github/workflows/ci.yml) runs `npx playwright test`, which includes the new file. Tests are not run in this TestForge run.

## Assumptions

- The product catalogue (PRODUCTS in src/catalogue.js) ships with the build, so every deployed environment shows the same products; tests import PRODUCTS and formatPrice from src/catalogue.js rather than copying values.
- Adding to the cart writes only the browser's cart cookie (public/app.js) and makes no server request, so it is read-only for the deployment and allowed in smoke.
- The app has no access control (no login), so no credentials are needed.
- Every first-party service runs for real: locally Playwright's existing webServer starts the shop; with BASE_URL set, the tests hit the deployed build. Nothing is faked.
