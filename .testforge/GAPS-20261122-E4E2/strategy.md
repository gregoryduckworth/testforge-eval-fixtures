# Test strategy: GAPS-20261122-E4E2 Write a smoke suite

Revision 1 · generated by TestForge

## Summary

Kettle & Co. has no smoke tests. Add a small Playwright smoke suite (tests/smoke/shop.spec.js), each test tagged @smoke, that checks the shop's critical paths through the configured baseURL using only GET requests and the browser-side cart cookie: the health endpoint, the catalogue, a product page, the cart and the checkout page. No test places an order (POST /orders, the only server write).

## Scope

**In scope**
- GET /health answers 200 with {status:'ok'}
- Catalogue home page lists every product with its price
- Product page reached from the catalogue shows name, price and an Add to cart button
- Adding to the cart (a browser cookie only) shows the line and total on the cart page
- Checkout page shows the order form for a non-empty cart, without submitting it

**Out of scope**
- Placing an order (POST /orders): it writes data on the server, so it stays with tests/checkout.spec.js
- Order confirmation page: it needs an order that only placing one creates
- Validation, empty states, 404 and error paths (fuller suite)

## Environment

Run with `npm run test:e2e -- --grep @smoke`; set BASE_URL to target a deployed build, otherwise playwright.config.js starts the shop on localhost:4175. Needs `npx playwright install chromium`.

## Assumptions

- Adding to the cart only sets a cookie in the test's own browser context (public/app.js) and sends no request to the server, so it counts as read-only for the deployed build.
- The product list comes from src/catalogue.js PRODUCTS, which is shipped code, not seeded data, so every environment built from the same commit shows it; tests import PRODUCTS and formatPrice rather than copying them.
- The suite reaches the app only through Playwright's baseURL (BASE_URL or the local default in playwright.config.js); no first-party service is faked. Locally the config's webServer starts the real shop.
- The shop has no sign-in, so no credentials are needed.
