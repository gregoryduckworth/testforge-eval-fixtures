# Test strategy: GAPS-20261122-1BB3 Keep API tests in step with the spec

Revision 1 · generated by TestForge

## Summary

Two operations in openapi.yaml have no test: GET /products/{id} (getProduct) and POST /orders/{id}/cancel (cancelOrder). Add tests of each one's success response and every error response the spec documents (404 for both, plus 409 for cancelling an order that is already cancelled). Each test checks the status, the JSON content type and the body shape the spec gives. Also, the existing GET /orders/{id} test still checks the old `totalCents` field. The spec (and commit bef1422) now returns `total` as a Money object, so that assertion is updated to the current contract.

## Scope

**In scope**
- GET /products/{id}: 200 Product and 404 Error
- POST /orders/{id}/cancel: 200 Order, 404 Error, 409 Error
- Updating the existing GET /orders/{id} success assertion to the spec's Order schema (total: Money), keeping everything else it checks

**Out of scope**
- Changes to the spec or the application
- Behaviour the spec does not document (e.g. stock returned on cancel)
- Restructuring existing tests beyond the ticket's needs (e.g. extracting the duplicated server setup); listed as a follow-up
