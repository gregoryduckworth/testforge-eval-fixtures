# Test strategy: SMOKE-20261120-5F35 Smoke check a deployment

Revision 1 · generated by TestForge

## Summary

Kettle & Co. has no smoke suite. Add one Playwright file, tests/smoke/shop.smoke.spec.js, with five fast read-only tests tagged @smoke that check the shop's critical paths through the configured baseURL: the health endpoint, the catalogue, a product page, adding to the cart (the cart is a browser cookie, so this writes nothing on the server) and reaching checkout with the order form. Placing an order is the only write (POST /orders), so it is left out.

## Scope

**In scope**
- GET /health
- Catalogue home page (/)
- Product page reached from the catalogue
- Adding to the cookie-held cart and seeing it on /cart
- Checkout page with the order form, not submitted

**Out of scope**
- Placing an order (POST /orders) and the confirmation page, because it creates an order on the server
- Validation, 404/405 and error pages (left to the fuller suite)

## Environment

The tests run against BASE_URL when it is set. Otherwise playwright.config.js starts node src/server.js on 4175. Run only the smoke tests with: npx playwright test --grep @smoke

## Assumptions

- The catalogue is hard-coded in src/catalogue.js (PRODUCTS), so every deployed build shows the same products. The tests import PRODUCTS rather than copying names and prices.
- Add to cart only writes the `cart` cookie in the browser (public/app.js). It sends no request and changes nothing on the server, so it counts as read-only. The checkout test sets the cart cookie through the browser context and does not submit the form.
- Nothing is faked: the tests use the real app at the configured baseURL (BASE_URL, or the local server that playwright.config.js starts).
- The shop has no sign-in, so the tests use no account.
