# Test strategy: CONTRACT-20261120-1A1A Keep API tests in step with the spec

Revision 1 · generated by TestForge

## Summary

The Orders API spec added POST /orders/{id}/cancel (cancelOrder) and changed GET /orders/{id} (getOrder): the 200 body now carries `total` {amount, currency} instead of `totalCents`, and `status` may be `cancelled`. The existing getOrder test asserts the old `totalCents` shape; it must assert the new `total` object, and new tests must cover cancelOrder's 200, 404 and 409 responses and the `cancelled` status on getOrder.

## Scope

**In scope**
- test/orders.test.js: update the getOrder 200 test to the new Order schema (only the totalCents -> total change)
- New tests for POST /orders/{id}/cancel: 200, 404, 409
- New getOrder case for status `cancelled`

**Out of scope**
- Other operations (listProducts, getProduct, placeOrder), which the spec did not change
- Stock restoration after a cancel: the spec doesn't document it
- Restructuring the existing server setup into a shared helper (not needed by this ticket; listed as a follow-up)

## Test case detail

### TC1: returns an order with its total

*integration · vitest · regression · high priority* — covers AC1

**Preconditions**
- App running in-process

**Steps**
1. Place an order for product 1, quantity 2
2. GET /orders/{id}

**Expected:** 200, application/json, body equals {id, productId: 1, quantity: 2, status: 'placed', total: {amount: 4998, currency: 'USD'}} (no totalCents)

**Test data:** productId 1 (Kettle, 2499), quantity 2

**Rationale:** getOrder (GET /orders/{id}): response 200 replaced totalCents with required total object; the existing test at test/orders.test.js:48 asserted the old contract.
