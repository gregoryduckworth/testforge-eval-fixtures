# Test strategy: CONTRACT-20261120-402E Keep API tests in step with the spec

Revision 1 · generated by TestForge

## Summary

Two Orders API operations have no test: GET /products/{id} (getProduct) and POST /orders/{id}/cancel (cancelOrder). Add vitest API tests beside the existing ones that call each by the spec's method and path against the in-process app, covering the 200 response and every documented error (404; plus 409 for cancel), asserting status, content type and body shape. Also bring the existing GET /orders/{id} success test up to the spec: it still asserts the old `totalCents` field, while the spec's Order now has `total: Money {amount, currency}`; only that property changes, every other check stays.

**In scope**
- GET /products/{id}: 200 and 404
- POST /orders/{id}/cancel: 200, 404 and 409
- Updating the existing GET /orders/{id} 200 assertion to the spec's Order.total Money shape

**Out of scope**
- Changing the spec or the application
- Operations already covered (listProducts, placeOrder, getOrder 404)
- Restructuring the existing specs (e.g. extracting the duplicated server setup) beyond what this ticket needs; listed as a follow-up
