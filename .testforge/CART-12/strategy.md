# Test strategy: CART-12 Bulk discount, coupons and free shipping at checkout

Revision 1 · generated by TestForge

## Summary

CART-12 prices the cart at checkout through cartTotal(items, { coupon }) in src/cart.js: a 10% bulk discount at 10+ items in total, the SAVE5 coupon after the bulk discount with goods floored at $0, refusal of any other coupon, and shipping of $4.99 unless the discounted goods reach $50 (an empty cart is free). Unit tests in Vitest call cartTotal with literal carts and check the exact total. Reading the code shows a likely defect: bulkDiscount uses `itemCount > BULK_THRESHOLD`, so a cart of exactly 10 items gets no discount.

## Scope

**In scope**
- cartTotal pricing: bulk discount, SAVE5 coupon, coupon refusal, shipping and empty cart

**Out of scope**
- UI or API for checkout: the repo only has the pricing module

## Test case detail

### TC1: takes 10% off a cart of exactly 10 items over several lines

*unit · vitest · edge · critical priority* — covers AC1

**Steps**
1. cartTotal([{price:10,quantity:4},{price:10,quantity:6}])

**Expected:** 100 subtotal less 10% = 90, free shipping: total 90. Expected to fail (code uses > 10), kept with it.fails and recorded as a defect.

**Test data:** lines of 4 and 6 at $10

**Rationale:** Boundary of AC1, where the code looks wrong

### TC2: takes 10% off a cart of 11 items over several lines

### TC4: takes SAVE5 off after the bulk discount

*unit · vitest · positive · critical priority* — covers AC2

**Steps**

**Expected:** 110 - 11 - 5 = 94 (coupon first would give 94.5)

**Test data:** 11 x $10

## Assumptions

- Coupon codes match exactly and are case-sensitive, so 'save5' is another code and is refused (the code uses Object.hasOwn on { SAVE5 })
- Refusal is a thrown Error; the tests check it is an Error whose message names the submitted code, because the module exports no error code
- 'Goods' means subtotal less bulk discount less coupon, floored at 0, which is what the shipping threshold applies to

## Open questions

- bulkDiscount uses `> BULK_THRESHOLD` (10), so exactly 10 items gets no discount, against AC1's '10 or more'. TC1 is kept as an expected failure and reported as a defect.
