# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, purely client-side state served by server.js) lets users tick todos complete, filter All/Active/Completed and clear completed ones. Playwright e2e tests against the real app prove the checkbox toggles strike-through and the "items left" count both ways, each filter shows exactly the right todos and is aria-pressed, and "Clear completed" is shown only while something is completed and removes all completed todos.

## Scope

**In scope**
- Completing/uncompleting a todo via its checkbox (strike-through, items-left count)
- All/Active/Completed filters and their pressed state
- Clear completed visibility and behaviour

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; ticket doesn't ask)

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count text and pluralisation drift ("1 item left" vs "2 items left") | medium | Assert the exact count text before and after toggling. |
| Filter could hide the wrong items or not re-render after a toggle | high | Assert exact list contents per filter with mixed completed/active todos. |
| Clear completed could remove active todos or only one completed todo | high | Clear with two completed and one active todo, assert exactly the active one remains. |

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Assert '2 items left'
3. Tick 'Buy milk' checkbox

**Expected:** Checkbox checked, 'Buy milk' text has line-through, 'Walk dog' does not, count reads '1 item left'

**Test data:** Two todo titles

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and restores items left

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Fresh page

3. Assert '1 item left'

**Expected:** Checkbox unchecked, text not line-through, count reads '2 items left'

## Environment

Uses the existing playwright.config.js webServer (node server.js on port 4173, baseURL http://localhost:4173). Browsers must be installed (npx playwright install chromium).

## Assumptions

- The real app runs via the existing playwright.config.js webServer (node server.js); nothing is faked. State is in-page memory, so every test starts from a fresh page and creates its own todos through the UI, which makes tests independent.
- "Struck through" is asserted as the todo text's computed text-decoration-line being line-through (the app applies it through li.completed span in styles.css), plus the checkbox's checked state.
- The only refusal-like behaviour in scope is that Clear completed is not offered when nothing is completed; the app has no other way to refuse these actions.
