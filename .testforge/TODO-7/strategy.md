# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, in-memory state per page load) lets users tick/untick todos, filter All/Active/Completed (aria-pressed buttons) and clear completed todos. The tests drive the real UI and real static server in Chromium and prove the strike-through and count change, the filter contents and pressed state, and the visibility and effect of "Clear completed".

## Scope

**In scope**
- Completing/uncompleting a todo via its checkbox (strike-through, items-left count)
- All / Active / Completed filters: list contents and aria-pressed state
- Clear completed: visibility and removal of completed todos

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (app keeps todos in memory only; the ticket doesn't ask for it)

## Risks

| Risk | Impact | Mitigation |

| Clear completed removing only one todo, or active ones, or staying visible | medium | TC7 clears two completed todos amid an active one; TC6 checks hidden/visible transitions |

## Test case detail

### TC1: ticking a todo strikes it through and decrements the items left count

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page at /

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Check that '2 items left' shows
3. Tick the 'Buy milk' checkbox

**Expected:** 'Buy milk' checkbox is checked and its title has text-decoration-line line-through; 'Walk dog' is not struck through; count reads '1 item left'

**Test data:** Titles 'Buy milk', 'Walk dog'

**Rationale:** Core completion behaviour

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). Needs Chromium installed. No other services.

## Assumptions

- Nothing is faked: server.js only serves static files and runs for real via Playwright's existing webServer config; all todo state lives in page memory, so each test starts from an empty list in its own page and needs no cleanup.
- None of these actions can be refused by the app (no validation on tick, filter or clear), so the negative case is that 'Clear completed' stays hidden when nothing is completed (TC6).
- "Struck through" is checked as the computed style text-decoration-line: line-through on the todo's title span (styles.css: li.completed span), which is what the user sees.
- Todos are created through the UI (label 'What needs doing?' + Add), as the existing spec does; locators use roles and exact accessible names.

## Open questions

- The existing playwright.config.js webServer uses port 4173, the same as `npm start`, with reuseExistingServer outside CI; TestForge's runner fixes BASE_URL to that port, so the tests keep it. Moving the test server to its own port is a follow-up.
