# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, in-memory state per page) lets users tick todos complete, filter All/Active/Completed with aria-pressed on the selected filter button, and clear completed todos with a button that is hidden unless a todo is completed. Playwright e2e tests against the real static server must prove each criterion through what the user sees: strike-through, the items-left count, the listed titles, pressed state and the Clear completed button.

## Scope

**In scope**
- Completing and un-completing todos via the checkbox (strike-through and items-left count)
- All / Active / Completed filters and their pressed state
- Clear completed visibility and behaviour

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js) beyond using it as setup
- Persistence across reloads (app keeps todos in memory only; ticket doesn't ask)
- Editing or deleting single todos (not in ticket)

## Acceptance criteria coverage

| AC | Criterion | Test cases |

| AC1 | Ticking a todo's checkbox marks it completed: it is struck through and the items-left count goes down by one; unticking reverses both. | TC1, TC2 |
| AC2 | Active shows only not-completed todos, Completed only completed ones, All every todo; the selected filter is shown as pressed. | TC3, TC4, TC5, TC6 |
| AC3 | "Clear completed" is shown only while at least one todo is completed, and removes every completed todo. | TC7, TC8 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count or filter logic regression leaves wrong todos visible or wrong count | high | Assert exact title arrays (in order) and exact count text in every case |
| Clear completed removes active todos or only one completed todo | high | TC7 clears two completed todos among an active one and asserts the remaining list exactly |
| Re-render under a filter detaches the checkbox, causing flaky check() calls | medium | Use click() on the checkbox where the row leaves the view and assert the resulting list |

## Test case detail

### TC1: ticking a todo strikes it through and lowers the items-left count by one

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page with todos 'Buy milk' and 'Walk dog'

**Steps**
1. Check that 'Buy milk' is not struck through and count reads '2 items left'
2. Tick 'Buy milk'

**Expected:** Checkbox checked, 'Buy milk' title has line-through, 'Walk dog' doesn't, count reads '1 item left'

**Test data:** Buy milk, Walk dog

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and raises the count again

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Fresh page with 'Buy milk' and 'Walk dog', 'Buy milk' ticked (1 item left)

**Steps**
1. Untick 'Buy milk'

**Expected:** Checkbox unchecked, no line-through, count reads '2 items left'

**Test data:** Buy milk, Walk dog

**Rationale:** Reverse transition

### TC3: Active filter shows only todos that aren't completed and is shown as pressed

### TC7: Clear completed is hidden until a todo is completed and hidden again once it is unticked

*e2e · playwright · negative · high priority* — covers AC3

**Preconditions**

**Steps**
1. Assert list loaded and Clear completed hidden
2. Tick 'Buy milk' and assert button visible
3. Untick 'Buy milk'

**Expected:** Button hidden, then visible, then hidden again

**Rationale:** Button is unavailable when there is nothing to clear

### TC8: Clear completed removes every completed todo and keeps the active ones

*e2e · playwright · positive · critical priority* — covers AC3

**Preconditions**

**Steps**
1. Click Clear completed

**Expected:** List shows exactly ['Walk dog'], count '1 item left', Clear completed hidden

**Rationale:** Removes all completed, not just one, and no active ones

## Environment

Playwright webServer in playwright.config.js starts `node server.js` on http://localhost:4173 (BASE_URL in runs). No backend, no seed data.

## Assumptions

- The real app runs for real: Playwright's existing webServer starts node server.js on 4173; nothing is faked (no backend API exists; state lives in the page).
- Each test opens a fresh page, so todos are isolated per test without cleanup.
- 'Struck through' is checked as the computed text-decoration-line: line-through of the todo's title span (styles.css li.completed span), and its absence when not completed.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others, as app.js sets it.
