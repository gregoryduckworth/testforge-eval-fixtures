# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, static, in-memory state per page load) lets users tick todos to complete them, filter All/Active/Completed with aria-pressed on the selected filter, and clear completed todos. The tests drive the real app served by server.js through Playwright's existing webServer and prove each acceptance criterion through what the user sees: list contents, line-through styling, the "N items left" text, pressed state and the Clear completed button's visibility.

## Scope

**In scope**
- Completing and un-completing a todo via its checkbox (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Clear completed visibility and removal

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js; used here only as setup)
- Persistence across reloads (the app keeps todos in memory only; the ticket doesn't ask for it)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | Ticking a todo's checkbox marks it completed: its title is struck through and the items-left count drops by one; unticking reverses both. | TC1, TC2 |
| AC2 | Active shows only incomplete todos, Completed only completed ones, All shows every todo; the selected filter button is pressed (aria-pressed=true) and the others are not. | TC3, TC4, TC5 |
| AC3 | "Clear completed" is shown only while at least one todo is completed, and clicking it removes every completed todo and keeps active ones. | TC6, TC7 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count text not updated on toggle, or untick not reversing completion | high | TC1 and TC2 assert the exact count text and the style before and after each toggle |
| Filter predicate wrong or pressed state left on the previous filter | medium | TC3-TC5 assert the exact list contents and aria-pressed of all three filter buttons |
| Clear completed removes active todos too, or shows when nothing is completed | high | TC6 asserts it is hidden with no completed todos and after unticking; TC7 asserts only the active todo remains |

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- App open at /

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Assert '2 items left' and 'Buy milk' not struck through
3. Tick 'Buy milk' checkbox

**Expected:** 'Buy milk' checkbox is checked, its title has text-decoration-line line-through, 'Walk dog' is not struck through, and the count reads '1 item left'

**Test data:** Two todo titles

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo restores it and increments items left

## Environment

Playwright's existing webServer starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). No seed data; each test builds its todos through the UI.

## Assumptions

- The real app runs for real via the existing playwright.config.js webServer (node server.js on 4173); nothing is faked, since there is no backend beyond static files.
- Todos live in page memory, so each test starts from an empty list on page.goto('/') and creates its own todos through the UI; no cross-test cleanup is needed.
- 'Struck through' is checked as the computed style text-decoration-line: line-through on the todo's title text (from styles.css li.completed span), not via the class name.
- 'Items left' uses the app's wording '1 item left' / 'N items left'.
