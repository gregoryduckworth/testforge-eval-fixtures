# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (static public/app.js served by server.js) lets users tick todos complete, filter by All/Active/Completed, and clear completed todos. E2E Playwright tests must prove the strike-through and "items left" count follow the checkbox both ways, each filter shows exactly the right todos and is marked aria-pressed, and "Clear completed" is shown only while something is completed and removes all completed todos only.

## Scope

**In scope**
- Completing/uncompleting a todo via its checkbox (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Visibility and behaviour of the Clear completed button

**Out of scope**
- Adding todos beyond what setup needs (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; not in the ticket)

*e2e · playwright · positive · critical priority* — covers AC1

**Steps**

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` at http://localhost:4173; chromium browser must be installed.

## Assumptions

- The real app runs: Playwright's existing webServer starts `node server.js` on port 4173; nothing is faked (there is no backend API, state lives in page memory).
- Todo state is per page load, so each test creates its own todos through the UI and tests are independent.
- "Struck through" is checked as the computed text-decoration-line: line-through on the todo's title, which is what the user sees (styles.css applies it to completed items).
- "Shown as pressed" means aria-pressed="true" on the selected filter button and "false" on the others.
