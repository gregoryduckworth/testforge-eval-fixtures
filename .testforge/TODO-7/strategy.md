# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (static public/app.js served by server.js, all state in memory in the page) lets users tick todos to complete them, filter by All/Active/Completed and clear completed todos. Tests must prove the strike-through and "items left" count follow the checkbox, each filter shows exactly the right todos and is aria-pressed, and "Clear completed" is shown only while something is completed and removes all completed todos.

## Scope

**In scope**
- Completing/uncompleting todos via the checkbox (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Visibility and behaviour of the Clear completed button

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js, TODO-7 doesn't change it)
- Persistence across reloads (the app keeps todos in memory only; ticket doesn't ask for it)

## Acceptance criteria coverage

| AC | Criterion | Test cases |

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- App open at /

**Steps**
1. Add 'Walk dog' and 'Pay rent'
2. Check '2 items left' and 'Walk dog' not struck through

**Expected:** 'Walk dog' checkbox checked, its title has text-decoration-line line-through, 'Pay rent' does not, count reads '1 item left'

**Test data:** Two todo titles

## Environment

Playwright webServer runs `node server.js` on http://localhost:4173 (existing config); chromium browser required. No env vars or seed data.

## Assumptions

- The real app runs: Playwright's existing webServer starts `node server.js` on port 4173; nothing is faked (there is no backend API, state lives in the page).
- Each test gets a fresh page, so todos never leak between tests; titles are still unique per test for readability.
- 'Struck through' is asserted as computed text-decoration-line: line-through on the todo's title text (styles.css), the user-visible outcome; the 'completed' class itself is not asserted.
- Todos are created through the UI the same way tests/add-todo.spec.js does (label 'What needs doing?' + Add button).
