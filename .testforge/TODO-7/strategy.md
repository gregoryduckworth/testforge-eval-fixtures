# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The static todo app (public/app.js) already implements completing, filtering and clearing todos in-browser with in-memory state. Playwright e2e tests must prove that ticking/unticking toggles strike-through and the "items left" count, that All/Active/Completed filters show the right todos and mark the selected one pressed (aria-pressed), and that "Clear completed" is shown only while a todo is completed and removes every completed todo.

## Scope

**In scope**
- Completing and un-completing a todo via its checkbox (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Clear completed visibility and behaviour

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js; used only as setup)
- Persistence across reloads (the app keeps state in memory only; ticket doesn't ask for it)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | Ticking a todo's checkbox marks it completed: it is struck through and the items-left count goes down by one; unticking reverses both. | TC1, TC2 |
| AC2 | Active shows only not-completed todos, Completed only completed ones, All every todo; the selected filter is shown as pressed. | TC3, TC4, TC5 |
| AC3 | "Clear completed" appears only while at least one todo is completed, and removes every completed todo. | TC6, TC7 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count not updated or updated by the wrong amount on toggle | high | TC1/TC2 assert the exact count text before and after with three todos |
| Filter shows wrong subset or pressed state out of sync | medium | TC3-TC5 assert exact list contents and aria-pressed on all three buttons |
| Clear completed removes active todos or only some completed ones | high | TC7 uses two completed and one active todo and asserts the exact remaining list |

## Test case detail

### TC1: ticking a todo strikes it through and decreases the items left count

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- App open at /

**Steps**
1. Add todos 'Buy milk', 'Walk dog', 'Pay rent'
2. Assert '3 items left' and 'Walk dog' not struck through
3. Tick the checkbox of 'Walk dog'

**Expected:** Checkbox checked, 'Walk dog' text has line-through, others don't, count reads '2 items left'

**Test data:** Three todo titles

**Rationale:** Core completion behaviour

## Environment

No services beyond the static server started by playwright.config.js webServer (node server.js, port 4173). Chromium via Playwright.

## Assumptions

- The real app runs: there is no API, todos live in page memory, so nothing is faked; each test gets fresh state from its own page and adds its own todos through the UI.
- The app is served by the existing playwright.config.js webServer (node server.js on 4173, which run_tests' BASE_URL also targets); the config is left unchanged.
- 'Struck through' is asserted as the todo text's computed text-decoration-line being 'line-through' (the user-visible effect of styles.css), located by role/text, never by CSS class.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others, as app.js sets it.
- The app has no refusals for these actions; the negative case is that Clear completed is not offered while nothing is completed.
