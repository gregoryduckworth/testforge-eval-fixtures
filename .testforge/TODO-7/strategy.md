# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, static, in-memory state) lets users tick todos complete, filter the list (All/Active/Completed with aria-pressed) and clear completed todos. Playwright e2e tests against the real static server prove that ticking strikes a todo through and lowers the count (and unticking reverses it), each filter shows the right subset and is pressed, and Clear completed appears only while something is completed and removes every completed todo.

## Scope

**In scope**
- Completing/uncompleting todos: strike-through and items-left count
- All / Active / Completed filters and their pressed state
- Clear completed visibility and behaviour

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; ticket doesn't ask for it)

## Test case detail

### TC1: ticking a todo strikes it through and lowers the items left count

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Tick 'Buy milk' checkbox

**Expected:** 'Buy milk' title has line-through, 'Walk dog' doesn't; count goes from '2 items left' to '1 item left'; checkbox checked

**Test data:** Buy milk, Walk dog

**Rationale:** Core completion journey

### TC2: unticking a completed todo removes the strike-through and restores the count

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add two todos
2. Tick 'Buy milk'
3. Untick 'Buy milk'

**Expected:** 'Buy milk' has no line-through, count back to '2 items left', checkbox unchecked

**Test data:** Buy milk, Walk dog

**Rationale:** Reversal half of AC1

### TC3: Active filter shows only todos that aren't completed and is pressed

*e2e · playwright · positive · high priority* — covers AC2

2. Tick 'Walk dog'

**Expected:** List is exactly ['Buy milk', 'Pay rent']; Active aria-pressed=true, All and Completed false

### TC7: Clear completed is hidden while no todo is completed

*e2e · playwright · negative · medium priority* — covers AC3

**Preconditions**
- Fresh page

**Steps**
1. Add a todo; assert it's listed
2. Assert Clear completed hidden
3. Tick it; assert visible

**Expected:** Hidden with only active todos, visible after ticking, hidden again after unticking

**Test data:** Buy milk

**Rationale:** Refusal side: the action isn't offered when nothing is completed

## Environment

Playwright's webServer starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). No env vars or seed data.

## Assumptions

- The real app runs: Playwright's existing webServer starts `node server.js`, a static server with no backend API; nothing is faked.
- State lives in the page's memory, so each test starts from an empty list on a fresh page and creates its own todos through the UI — no cross-test data.
- 'Struck through' is checked as computed `text-decoration-line: line-through` on the todo's title, which is what styles.css applies to completed items.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others (what app.js sets).
