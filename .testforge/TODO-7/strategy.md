# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js) lets users tick todos complete, filter by All/Active/Completed (aria-pressed on the selected button) and clear completed todos. State lives in browser memory per page load, so each Playwright test starts from an empty list and adds its own todos. The tests prove the strike-through and count change, each filter's contents and pressed state, and the visibility and effect of "Clear completed".

## Scope

**In scope**
- Completing/uncompleting a todo via its checkbox: strike-through and items-left count
- All / Active / Completed filters: listed todos and aria-pressed state
- Clear completed: visibility rule and removal of every completed todo

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | Ticking a todo's checkbox marks it completed (struck through) and lowers the items-left count by one; unticking reverses both. | TC1, TC2 |
| AC2 | Active shows only uncompleted todos, Completed only completed ones, All every todo; the selected filter is shown as pressed. | TC3, TC4, TC5 |
| AC3 | "Clear completed" is shown only while at least one todo is completed, and clicking it removes every completed todo. | TC6, TC7 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count text or pluralisation regressions ('1 item left' vs '2 items left') | medium | Assert exact count text before and after ticking/unticking |
| Filter shows wrong todos or wrong pressed state | high | Each filter tested with a mix of completed and active todos, asserting the exact list and aria-pressed of all three buttons |
| Clear completed removes active todos or only one completed todo | high | Clear with two completed and one active todo, assert exact remaining list |

## Test case detail

### TC1: ticking a todo strikes it through and lowers the items left count

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page with todos 'Buy milk' and 'Walk dog' added

**Steps**
1. Tick the 'Buy milk' checkbox

**Expected:** 'Buy milk' checkbox is checked, its text has text-decoration-line line-through, 'Walk dog' is not struck through, count reads '1 item left' (was '2 items left')

**Test data:** Buy milk, Walk dog

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and restores the count

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**

**Steps**
1. Untick 'Buy milk'

**Expected:** Checkbox unchecked, text-decoration-line none, count reads '2 items left'

**Test data:** Buy milk, Walk dog

**Rationale:** Reversal half of AC1

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). Chromium must be installed. No seed data or env vars.

## Assumptions

- No backend: server.js only serves static files, so nothing is faked; Playwright's existing webServer starts the real server.
- Todos are held in page memory, so every test gets an empty list on page.goto('/') and creates its own data; no cleanup needed.
- 'Struck through' is checked as the todo text's computed text-decoration-line being line-through (styles.css: li.completed span).
- Absence assertions are made with exact list contents (toHaveText on the whole list), which wait for the expected items to render.
