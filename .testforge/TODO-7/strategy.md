# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todos app (public/app.js, served by server.js) lets users tick todos complete, filter All/Active/Completed and clear completed todos. The tests prove, in a real browser against the real static server, that ticking and unticking update the strike-through and the items-left count, that each filter shows the right todos and is pressed, and that "Clear completed" is shown only while a todo is completed and removes every completed todo.

## Scope

**In scope**
- Completing and un-completing todos (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Visibility and effect of Clear completed

**Out of scope**
- Persistence across reloads (the app keeps todos in page memory only; the ticket doesn't ask for it)
- Adding todos (covered by tests/add-todo.spec.js)

## Acceptance criteria coverage

| AC | Criterion | Test cases |
|---|---|---|
| AC1 | Ticking a todo's checkbox marks it completed: it is struck through and the items-left count goes down by one; unticking reverses both. | TC1, TC2 |
| AC2 | Active shows only non-completed todos, Completed only completed ones, All every todo; the selected filter is shown as pressed. | TC3, TC4, TC5 |
| AC3 | "Clear completed" is visible only while at least one todo is completed, and clicking it removes every completed todo (and only those). | TC6, TC7 |

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count could be computed from visible (filtered) todos instead of all todos | medium | TC3 also asserts the items-left count stays based on all todos while filtered. |
| Clear completed could remove active todos or leave some completed ones | high | TC7 completes two of three todos and asserts only the active one remains. |
| Unticking could leave stale strike-through or count | medium | TC2 asserts both reverse. |

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Assert '2 items left'
3. Tick 'Buy milk'

**Expected:** 'Buy milk' checkbox checked, its title has line-through, 'Walk dog' not struck through, count reads '1 item left'

**Test data:** Buy milk, Walk dog

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and restores items left

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add two todos
2. Tick 'Buy milk', assert '1 item left'
3. Untick 'Buy milk'

**Expected:** Checkbox unchecked, no line-through, '2 items left'

**Test data:** Buy milk, Walk dog

**Rationale:** Reversal path of AC1

### TC3: Active filter shows only todos that aren't completed and is pressed

## Environment

Playwright's webServer starts `node server.js` on port 4173 (existing config); no env vars or seed data. Browsers must be installed (`npx playwright install chromium`).

## Assumptions

- The app is a static page served by the repo's own server.js; it runs for real via playwright.config.js webServer. Nothing is faked: there is no backend API, todos live in page memory, so each test starts from an empty list on a fresh page and tests are independent.
- "Struck through" is checked as the computed text-decoration line-through on the todo's title, which is how styles.css renders a completed todo; the checked checkbox is asserted too.
- "Shown as pressed" means aria-pressed="true" on the selected filter button and "false" on the others.
