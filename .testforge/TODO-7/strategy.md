# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (static public/app.js, in-memory state per page load, served by server.js) already implements completing, filtering and clearing todos. The tests drive it in a browser with Playwright to prove: ticking strikes a todo through and lowers the "items left" count (unticking reverses it), the All/Active/Completed filters show the right todos and mark the selected one aria-pressed, and "Clear completed" shows only while something is completed and removes every completed todo.

## Scope

**In scope**
- Completing and un-completing todos via their checkbox (strike-through, items-left count)
- All / Active / Completed filters and their pressed state
- Clear completed visibility and behaviour

**Out of scope**
- Adding todos beyond what setup needs (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; ticket doesn't ask for it)

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Count not updated or struck-through state not reverted on untick | high | TC1 and TC2 assert both the style and the exact count text in both directions |
| Filter shows wrong items, or pressed state stays on the old filter | medium | TC3-TC5 assert the exact list contents and aria-pressed on all three buttons; TC8 checks the Active view updates on completion |
| Clear completed removes active todos or stays visible with nothing completed | high | TC6 covers visibility both ways, TC7 checks only completed todos are removed and the button hides |

## Test case detail

### TC1: ticking a todo strikes it through and lowers the items left count

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- App open with todos 'Buy milk' and 'Walk dog' added (2 items left)

**Steps**
1. Tick the 'Buy milk' checkbox

**Expected:** Checkbox checked; 'Buy milk' text has text-decoration-line line-through; 'Walk dog' not struck through; count reads '1 item left'

**Test data:** Two todo titles

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and restores the count

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Two todos added, 'Buy milk' ticked (1 item left)

**Steps**
1. Untick 'Buy milk'

**Expected:** Checkbox unchecked; text-decoration-line is none; count reads '2 items left'

**Test data:** Two todo titles

**Rationale:** Reverse transition

### TC3: Active filter shows only todos that are not completed and is pressed

*e2e · playwright · positive · high priority* — covers AC2

**Preconditions**
- Todos 'Buy milk' (completed) and 'Walk dog' added

**Steps**
1. Click Active

**Expected:** List items exactly ['Walk dog']; Active aria-pressed=true, All and Completed false

**Rationale:** Filter correctness

### TC4: Completed filter shows only completed todos and is pressed

*e2e · playwright · positive · high priority* — covers AC2

**Preconditions**
- Todos 'Buy milk' (completed) and 'Walk dog' added

**Steps**
1. Click Completed

**Expected:** List items exactly ['Buy milk']; Completed pressed, others not

**Rationale:** Filter correctness

### TC5: All filter shows every todo again and is pressed

*e2e · playwright · positive · medium priority* — covers AC2

**Preconditions**
- Todos 'Buy milk' (completed) and 'Walk dog'; Completed filter selected

**Steps**
1. Click All

**Expected:** List items exactly ['Buy milk', 'Walk dog']; All pressed, others not

**Rationale:** Returning to All restores the full list

### TC6: Clear completed is shown only while a todo is completed

*e2e · playwright · negative · high priority* — covers AC3

**Preconditions**
- One todo 'Buy milk' added

**Steps**
1. Check Clear completed is hidden
2. Tick the todo
3. Untick the todo

**Expected:** Hidden before ticking (todo visible in list), visible after ticking, hidden again after unticking

**Rationale:** Refusal side: no clear action offered when nothing is completed

### TC7: Clear completed removes every completed todo and keeps active ones

*e2e · playwright · positive · critical priority* — covers AC3

**Preconditions**
- Todos 'Buy milk', 'Walk dog', 'Pay rent' added; 'Buy milk' and 'Pay rent' ticked

**Steps**
1. Click Clear completed

**Expected:** List items exactly ['Walk dog']; count '1 item left'; Clear completed hidden

**Test data:** Three titles

**Rationale:** Removes all, not only one, completed todo and nothing else

### TC8: ticking a todo while the Active filter is selected removes it from the list

*e2e · playwright · edge · medium priority* — covers AC2

**Preconditions**

**Steps**

**Expected:** List items exactly ['Walk dog']; count '1 item left'

**Rationale:** Filter view stays consistent as state changes

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). No env vars, seed data or backend needed.

## Assumptions

- The real app runs: Playwright's existing webServer starts `node server.js`; nothing is faked (there is no backend API, state lives in the page).
- Each test gets a fresh page, so todos never leak between tests or retries; no cleanup is needed.
- 'Struck through' is asserted as the todo text's computed text-decoration-line being line-through (the visible effect), not by the `completed` CSS class.
- Todos are located by role (list 'Todos', listitem, checkbox named by its label text) with exact names.
