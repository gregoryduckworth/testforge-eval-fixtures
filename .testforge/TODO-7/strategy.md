# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, a client-side in-memory list served by server.js) lets users tick todos complete, filter All/Active/Completed and clear completed. E2E Playwright tests drive the real app through the UI and prove strike-through and the items-left count, filter contents and their pressed state, and the visibility and effect of "Clear completed".

## Scope

**In scope**
- Completing and un-completing a todo (strike-through, items left count)
- All/Active/Completed filters and aria-pressed state
- Clear completed visibility and removal

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (app has none; not in ticket)

## Acceptance criteria coverage

| AC | Criterion | Test cases |

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page with todos 'Buy milk' and 'Walk dog' added

**Steps**
1. Tick 'Buy milk' checkbox

**Expected:** 'Buy milk' checkbox checked, its text has line-through, 'Walk dog' not struck through, count reads '1 item left' (was '2 items left')

**Test data:** Buy milk, Walk dog

**Rationale:** Core completion behaviour

### TC2: unticking a completed todo removes the strike-through and restores items left

*e2e · playwright · positive · high priority* — covers AC1

**Preconditions**
- Fresh page with two todos, one ticked

**Steps**
1. Untick the ticked todo

**Expected:** Checkbox unchecked, text-decoration no longer line-through, count back to '2 items left'

**Test data:** Buy milk, Walk dog

**Rationale:** Reversal is explicitly required

## Environment

Playwright webServer starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). No backend data; state is per page.

## Assumptions

- State lives in memory per page load, so each test starts from an empty list on a fresh page and creates its own todos; no shared server state exists, the real static server (server.js) is started by playwright.config.js webServer, nothing is faked.
- 'Struck through' is checked as the computed text-decoration line-through on the todo's text (user-visible style), not via the CSS class.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others.
