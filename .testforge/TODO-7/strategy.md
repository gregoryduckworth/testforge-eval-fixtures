# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

TODO-7 adds completing, filtering and clearing todos to the static todo app (public/app.js, state held in memory in the page). The tests must prove, in a real browser against the app served by server.js, that ticking/unticking a todo toggles its strike-through and the "items left" count, that All/Active/Completed show the right todos and mark the selected filter pressed, and that "Clear completed" shows only while a todo is completed and removes every completed todo (and only those).

## Scope

**In scope**
- Completing and uncompleting a todo via its checkbox (strike-through and items-left count)
- All / Active / Completed filters and their aria-pressed state
- Clear completed visibility and removal of completed todos

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js; used only as setup)
- Persistence across reloads — the app keeps todos in memory only and the ticket does not ask for it

## Acceptance criteria coverage

## Risks

| Risk | Impact | Mitigation |

| Clear completed removes active todos too or stays visible | high | TC6 checks hidden when nothing completed; TC7 checks only completed are removed and button hides |

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- App open at /

**Steps**
1. Add todos 'Buy milk' and 'Walk dog'
2. Assert '2 items left' and 'Buy milk' text not struck through
3. Tick the 'Buy milk' checkbox

**Expected:** Checkbox checked; 'Buy milk' text has text-decoration-line line-through; 'Walk dog' not struck through; count reads '1 item left'

**Test data:** Titles 'Buy milk', 'Walk dog'

**Rationale:** Core completion behaviour

## Environment

Playwright's existing webServer starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). Chromium installed. No env vars, seeds or backend.

## Assumptions

- The real first-party server (server.js, started by Playwright's existing webServer config on port 4173) runs for real; nothing is faked. The app has no backend API or access control, so no auth cases apply.
- Todos live in page memory, so each test gets a fresh page and creates its own todos through the UI; tests share no state.
- 'Struck through' is asserted as the user-visible computed style text-decoration-line: line-through on the todo's text (from styles.css li.completed span), not the CSS class.
- The todo's checkbox is reached by role checkbox with the todo title as its accessible name (the label wraps the checkbox and title).
