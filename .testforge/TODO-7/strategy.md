# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The todo app (public/app.js, a client-side app with in-memory state, served statically by server.js) already implements completing, filtering and clearing todos. Browser tests in tests/ have to show that ticking a todo strikes it through and lowers the "items left" count, and that unticking reverses both. They also have to show that All/Active/Completed show the right todos with the selected filter pressed, and that "Clear completed" shows only while a todo is completed and removes every completed todo.

## Scope

**In scope**
- Checkbox completion/uncompletion with strike-through and items-left count
- All/Active/Completed filters and their aria-pressed state
- Clear completed visibility and removal of all completed todos

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; ticket doesn't ask for it)

## Risks

| Risk | Impact | Mitigation |

| Clear completed removes only some completed todos or leaves the button visible | medium | TC6 completes two of three todos (non-adjacent) and asserts only the active one remains and the button hides |

## Test case detail

### TC1: ticking a todo strikes it through and lowers the count, unticking reverses both

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Assert '2 items left', 'Buy milk' not struck through
3. Tick 'Buy milk' checkbox
4. Assert checkbox checked, text struck through, '1 item left'
5. Untick it
6. Assert unchecked, not struck through, '2 items left'

**Expected:** Count goes 2 -> 1 -> 2 and strike-through appears then disappears; 'Walk dog' never struck through

**Test data:** Todos 'Buy milk', 'Walk dog'

**Rationale:** Core behaviour of the ticket in both directions

### TC2: Active filter shows only todos that aren't completed and is shown as pressed

*e2e · playwright · positive · high priority* — covers AC2

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk', 'Walk dog', 'Pay rent'
2. Tick 'Walk dog'
3. Click Active

**Expected:** List is exactly ['Buy milk', 'Pay rent']; Active aria-pressed=true, All and Completed false

**Test data:** Three todos, one completed

**Rationale:** Filter correctness and pressed state

### TC3: Completed filter shows only completed todos and is shown as pressed

*e2e · playwright · positive · high priority* — covers AC2

**Preconditions**
- Fresh page

**Steps**
1. Add three todos, tick 'Walk dog'
2. Click Completed

**Expected:** List is exactly ['Walk dog']; Completed pressed, others not

**Test data:** Three todos, one completed

**Rationale:** Filter correctness and pressed state

### TC4: All filter shows every todo again after another filter and is shown as pressed

*e2e · playwright · positive · high priority* — covers AC2

**Preconditions**
- Fresh page

**Steps**
1. Add three todos, tick 'Walk dog'
2. Assert All pressed initially and list shows all three
3. Click Completed, then click All

**Expected:** List is all three todos in order; All pressed, others not

**Test data:** Three todos, one completed

**Rationale:** Returning to All must restore hidden todos

### TC5: Clear completed is hidden while no todo is completed

*e2e · playwright · negative · medium priority* — covers AC3

**Preconditions**
- Fresh page

**Steps**
1. Assert button hidden with empty list
2. Add a todo, assert hidden
3. Tick it, assert visible
4. Untick it, assert hidden

**Expected:** Button only visible while the todo is completed

**Test data:** Todo 'Buy milk'

**Rationale:** Visibility rule in both directions

### TC6: Clear completed removes every completed todo and keeps active ones

*e2e · playwright · positive · high priority* — covers AC3

**Preconditions**
- Fresh page

**Steps**
1. Add 'Buy milk', 'Walk dog', 'Pay rent'
2. Tick 'Buy milk' and 'Pay rent'
3. Click Clear completed

**Expected:** List is exactly ['Walk dog'], '1 item left', Clear completed hidden

**Test data:** Three todos, two non-adjacent completed

**Rationale:** Removal must cover every completed todo, not just one

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` on port 4173 (BASE_URL http://localhost:4173). No data or env vars needed. CI (.github/workflows/ci.yml) already runs `npm run test:e2e`.

## Assumptions

- There is no backend API to fake: the real server.js only serves static files and is started by the existing Playwright webServer config. Todos live in page memory, so each test starts with an empty list on a fresh page and creates its own todos through the UI. Nothing is faked.
- Strike-through is checked as the user sees it: the todo's text, found by role/text within its list item, has computed text-decoration-line 'line-through' (styles.css: li.completed span), and 'none' after unticking. No locator uses a CSS class.
- The count wording follows the code and the existing spec: '1 item left', 'N items left'.
