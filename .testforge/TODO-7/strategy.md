# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The static todo app (public/app.js) already implements completing via checkbox, All/Active/Completed filters with aria-pressed, and a "Clear completed" button hidden unless a todo is completed. The tests must prove, in a real browser against the real server, that ticking/unticking toggles the strike-through and "items left" count, each filter shows exactly the right todos and is shown pressed, and Clear completed appears only while something is completed and removes every completed todo.

## Scope

**In scope**
- Completing and un-completing a todo via its checkbox (strike-through, items left count)
- All / Active / Completed filters and their pressed state
- Visibility and effect of the Clear completed button

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js, used here only as setup)
- Persistence across reloads (the app keeps todos in memory only; the ticket doesn't ask for it)

## Risks

| Risk | Impact | Mitigation |
|---|---|---|
| Items-left count or strike-through not updating on untick (state toggled one way only) | high | TC2 ticks then unticks and asserts both the style and the count return. |
| Filters showing the wrong subset or the pressed state not following the selection | high | TC3-TC6 use a mixed list and assert the exact visible titles and aria-pressed on all three buttons. |
| Clear completed removing only one completed todo or active ones too | high | TC8 completes two non-adjacent of three todos and asserts exactly the active one remains. |

## Test case detail

### TC1: ticking a todo strikes it through and decreases items left by one

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Page opened at /

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Check '2 items left'
3. Tick the checkbox of 'Buy milk'

**Expected:** 'Buy milk' checkbox is checked and its title has text-decoration-line line-through; 'Walk dog' is not struck through; count reads '1 item left'.

**Test data:** Todos 'Buy milk', 'Walk dog'

**Rationale:** Core completion behaviour of AC1.

### TC2: unticking a completed todo removes the strike-through and restores items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Page opened at /

**Steps**
1. Add 'Buy milk' and 'Walk dog'
2. Tick 'Buy milk' and see '1 item left'
3. Untick 'Buy milk'

**Expected:** 'Buy milk' checkbox is unchecked, its title has text-decoration-line none, count reads '2 items left'.

**Test data:** Todos 'Buy milk', 'Walk dog'

**Rationale:** AC1 requires the reversal; a one-way toggle is a common bug.

## Environment

Playwright's existing webServer starts `node server.js` on port 4173 (BASE_URL http://localhost:4173); Chromium must be installed. No env vars or seed data.

## Assumptions

- Nothing is faked: the app is static files served by the real server.js, which Playwright's existing webServer config starts; there is no API. All state lives in page memory, so each test starts from an empty list and is independent.
- Todos are created through the UI (the label 'What needs doing?' and the Add button), as the existing spec does.
- 'Struck through' is asserted as the computed text-decoration-line 'line-through' on the todo's title, which styles.css applies to li.completed span.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others, as app.js sets it.
- List contents are asserted as the exact ordered list of titles (toHaveText on the list items), so an absence is checked against a list that is known to be rendered.
