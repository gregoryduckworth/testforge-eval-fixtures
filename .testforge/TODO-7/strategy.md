# Test strategy: TODO-7 Complete, filter and clear todos

Revision 1 · generated by TestForge

## Summary

The static todo app (public/app.js, in-memory state per page load) already supports completing, filtering and clearing todos. The tests must prove through the browser that ticking/unticking a todo toggles its strike-through and the "items left" count, that the All/Active/Completed filters show the right todos and mark the selected filter pressed, and that "Clear completed" shows only while a todo is completed and removes every completed todo.

## Scope

**In scope**
- Completing and un-completing a todo via its checkbox (strike-through, items-left count)
- All / Active / Completed filters and their aria-pressed state
- Visibility and effect of the Clear completed button

**Out of scope**
- Adding todos (covered by tests/add-todo.spec.js)
- Persistence across reloads (the app keeps todos in memory only; the ticket does not ask for it)

## Test case detail

### TC1: ticking a todo strikes it through and decrements items left

*e2e · playwright · positive · critical priority* — covers AC1

**Preconditions**
- Page loaded with an empty list

**Steps**
1. Add todos 'Buy milk' and 'Walk dog'
2. Assert '2 items left' and 'Buy milk' not struck through
3. Tick the 'Buy milk' checkbox

**Expected:** 'Buy milk' checkbox is checked, its text has text-decoration-line line-through, 'Walk dog' is not struck through, and the count reads '1 item left'.

**Test data:** Titles 'Buy milk', 'Walk dog'

**Rationale:** Core completion behaviour.

## Environment

Playwright's webServer in playwright.config.js starts `node server.js` on http://localhost:4173; Chromium must be installed. No env vars or seed data.

## Assumptions

- The real app runs: Playwright's existing webServer starts `node server.js` on port 4173 (the URL run_tests uses); nothing is faked, there is no backend API or access control.
- Todo state lives in page memory, so each test starts from an empty list by loading the page, and tests share no data.
- 'Struck through' is checked as the todo text's computed text-decoration-line being line-through (styles.css `li.completed span`), a user-visible style rather than the class name.
- 'Shown as pressed' means aria-pressed="true" on the selected filter button and "false" on the others (index.html / app.js).
